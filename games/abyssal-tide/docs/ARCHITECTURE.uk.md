# Abyssal Tide · Архітектура

Документ пов’язує розділи GDD з кодом. README англійською, описи модулів — українською.

## Шари

| Шар | Каталог | Відповідальність | Залежить від |
|---|---|---|---|
| Спільні типи | `src/shared` | Символи, таблиця виплат, лінії, контракт кроку, номінали Salvage | — |
| Рушій | `src/engine` | Чиста функція `step()`, оцінка ліній, RNG, стрічки барабанів, сценарний провайдер | shared |
| «Сервер» | `src/server` | Атомарна фіксація кроку, ідемпотентність `stepId`, сесія в `localStorage`, історія, replay, сценарії показу | engine |
| Клієнт | `src/client` | Стан-машина, Pixi-сцена, DOM-HUD, звук, банки 3 Pots, екрани й переходи | shared, server (лише інтерфейс `ResultSource`), пакети `@slotkit/*` |
| Пакети | `packages/*` | Перевикористовувані частини для наступних ігор (див. нижче) | pixi.js, gsap; один від одного лише за схемою нижче |
| Сервер | `server/` | HTTP API у стилі RGS навколо того самого рушія: сесії, транзакції Postgres, журнал коштів, криптографічний RNG | engine, shared, server/records + api (контракт) |

Рушій не знає про час, DOM чи сховище. Клієнт не знає правил: усе, що він показує, вже є в `StepResult`.

## Пакети `@slotkit/*`

Монорепо на npm workspaces. Пакети експортують TypeScript-джерела (`"exports": { ".": "./src/index.ts" }`), тож гра й пакети типізуються та збираються разом без окремого кроку збірки. Коли пакет знадобиться іншій грі, його можна винести в окремий репозиторій без змін API.

| Пакет | Що містить | Залежить від |
|---|---|---|
| `@slotkit/core` | Ігровий час на GSAP (`wait`, `play`, `Episode`, `Signal`), `runtime` (профіль швидкості й reduced motion), формат грошей у центах, журнал діагностики | gsap |
| `@slotkit/board` | Барабани (`ReelSet`, `Reel`, `StopPlan`), базовий `SymbolView` з пресетами руху, `WinPresenter`, олівцеві лінії, інтерфейс `SymbolPack` | core, pixi.js |
| `@slotkit/controls` | Кнопка «Спін» з утриманням, сітка ставок, автогра з умовами зупинки (`shouldStopAutoplay` — чиста функція), керування поповерами, `controls.css` | — |
| `@slotkit/paytable` | Таблиця виплат як дані → HTML (`renderPaytable`), `paytable.css` | — |
| `@slotkit/symbols-cyanotype` | Графіка цієї гри як пак символів: SVG-фотограми, текстури, пресети руху, сторінка-галерея | board, core |

Межа між грою й пакетами:

- `runtime` у `@slotkit/core` — єдиний канал налаштувань у пакети. Гра оновлює його в `settings.syncRuntime()`, коли гравець змінює швидкість чи рух; пакети не читають `prefs` гри.
- `client/view/SymbolView.ts` наслідує `SymbolView` з board і додає лише своє: бирки номіналів перлин, кольорову мітку банки, розкриття мушлі, кільце-хвилю для карти.
- `client/view/Reels.ts` збирає `ReelSet` зі стрічками режимів `base` / `freeDives` і заповнювачем перлин; `keepBright` — тригерні символи гри.
- `Hud.ts` створює `BetPanel`, `AutoplayPanel`, `Popovers`, `bindSpinButton` і дає їм значення, підписи (i18n) та колбеки; id і `data-*` атрибути збережені, тож e2e-тести не змінювалися.
- Таблиця виплат у `Hud.paytable()` — це модель розділів; розмітку будує `renderPaytable`, суми гра передає вже в євро для поточної ставки.

## Рушій (GDD §2)

- Гроші — цілі центи EUR (`shared/config.ts`): 16 рівнів ставки від €0.25 до €50, як у слотах 3 Oaks; ставки GDD 1/2/5/10 — це €1/€2/€5/€10 серед них, старт 1000 кредитів GDD = €1 000.00. Усі виплати кратні ставці, тож дробових центів не буває; клієнт лише форматує суми (`client/core/format.ts`). Ключі збереження — `session/v3` і `prefs/v3`, бо одиниці балансу змінилися.

- `step(state, request, provider)` повертає новий стан і результат; вхідний стан не змінюється (`structuredClone`). Це дозволяє «серверу» записати обидва одним `set`.
- Дії: `spin` (одне списання), `freeSpin` (без списання, лічильник −1 разом із прийняттям результату), `respin`, `collect` (бонусна виплата зараховується один раз).
- Порядок одночасних тригерів зашитий у `reelStep`: лінії → +8 FS → Salvage. Наступна дія визначається `nextAction()`: Salvage завжди перед продовженням серії.
- Super: прапорець `superActive` у стані Salvage. Номінал перлини рахується як `v × 2` у момент показу та виплати (`cellValue`), тож подвоєння відбувається рівно один раз і поширюється на майбутні перлини. Чорна перлина — власні 10 ставок.
- 3 Pots (`engine.ts`, `outcome.ts`, `model.ts`): у базовій грі перлина з імовірністю `POT_MARK_CHANCE` отримує мітку `cell.pot`. Мітки наповнюють банки поточної ставки (`state.pots[bet]`, до `POT_SIZE` = 30) ще до перевірки тригера Salvage, тож мітка на тригерному спіні вже рахується. `startSalvage` забирає повні банки в `SalvageState.mods` і обнуляє їх: Extra — `RESPINS_EXTRA` = 4 респіни й скидання до 4; Boost — `+b` до кожної стартової перлини (лише стартової); Multi — у `finishSalvage` 1–3 випадкові перлини отримують `m` ×2/×3/×5. Номінал клітини рахує `cellValue`: `v × (m ?? 1) × (super ? 2 : 1)`. У Free Dives мітки не випадають, але повна банка все одно спрацьовує в Salvage.
- Mystery розкриваються наприкінці (`finishSalvage`) у порядку «згори вниз, зліва направо». Перше розкриття Super вмикає подвоєння до підрахунку суми.
- `OutcomeProvider` відокремлює випадковість від правил: `RandomOutcomeProvider` (стрічки + ваги з `model.ts`) і `ScriptedOutcomeProvider` (нотація `'P2 R3 M …'` для тестів і показу бонусу).

## Справжній сервер (`server/`)

Рушій той самий, що й в офлайн-демо: `server/src/service.ts` викликає `step()` і додає лише те, чого браузер сам не зробить.

- **Сесія.** `POST /api/launch { playerId, jurisdiction }` створює гравця (якщо новий) і повертає токен, стан для відновлення, історію й правила ринку. Далі — `Authorization: Bearer`.
- **Крок.** `POST /api/play { stepId, action, bet }` — одна транзакція: `SELECT … FOR UPDATE` на `game_state` гравця → пошук кроку з цим `stepId` (будь-якого, не лише останнього) → `step()` → запис кроку, журналу (`bet` −, `win` +), завершеного раунду й нового стану → `COMMIT`. Два однакові запити одночасно виконуються по черзі, і другий знаходить уже записаний крок.
- **RNG.** `createCryptoRng()` (`src/engine/rng.ts`): `crypto.getRandomValues`, цілі без зсуву (відкидання). Офлайн-демо й симуляція — mulberry32 із сидом.
- **Сховище.** `MemoryRepository` (тести, запуск без бази) і `PgRepository` (`server/src/pg.ts`, схема там само) з однаковою поведінкою; один набір API-тестів ганяється на обох (`npm run test:pg`).
- **Клієнт.** `RemoteResultSource` реалізує той самий `LiveSource`, що й `LocalResultSource`: GameFlow не знає, звідки результати. `?server=` або `VITE_SERVER_URL` вмикає сервер; якщо він недоступний — офлайн і повідомлення. 401 (сервер перезапущено без бази) — новий запуск і той самий запит.
- **Запуск.** `docker compose up --build` — Postgres, сервер і зібрана гра за nginx.

## Ринки й максимальний виграш

- `GameRules { maxWinX }` (`shared/config.ts`) передається в `step()`. Виплату обрізає `capped()`: межа досягнута — раунд закінчується, Free Dives і Salvage згоряють, у кроці `maxWin: true`, клієнт показує штамп Max win.
- `shared/jurisdiction.ts`: профілі `default` і `ukgc` (UKGC RTS 14, 14E, 14F, 8, 2E, 13C). Вибір — параметр запуску `?jurisdiction=` або налаштування (з перезапуском, бо ринок фіксується на старті сесії, як у оператора).
- Як GameFlow їх виконує: мінімальний цикл 2,5 с витрачається на довше обертання (`holdForMinCycle`), а кнопка лишається неактивною лише залишок; quick stop, утримання, швидкості й автогра вимикаються; виграш ≤ ставки показується лініями без бирки, звуку й підсвітки; рядок «Результат / Час» і нагадування про час гри (`startSessionClock`, `realityCheck`) — гра чекає відповіді.

## Екран (`client/core/viewport.ts`)

- Компонування за орієнтацією: `h > w` — портрет (керування рядком під полем), інакше альбом (стовпчик праворуч), і на телефоні теж. Раніше медіазапит за шириною давав телефону в альбомі портретний HUD і мініатюрне поле.
- `--k` (кнопки) і `--kb` (смуга балансу) масштабують HUD від розміру екрана; `--inset-x` тримає керування біля гри на моніторах ширших за 21:10; безпечні зони — `viewport-fit=cover` і `env(safe-area-inset-*)`, JS читає їх через прихований елемент.
- `GameView.fitScale()` порівнює обидві композиції поля (портретну 928×1068 і широку 1100×748) і бере ту, де поле більше (портретну — навіть трохи дрібнішою, бо бирки читаються краще). В альбомі гра центрується на екрані, якщо поле від цього не меншає.
- Низькі екрани (`max-height: 520px` в альбомі): стартовий екран у чотири картки, компактні екрани бонусів, автогра у дві колонки.

## Ассети (`npm run assets`)

`scripts/build-assets.ts`: Vite піднімає `scripts/art/` → Playwright/Chrome растеризує символи паку й частини «Водолаза» → `raw-assets/*{tps}` → AssetPack (`texturePacker`, `compress`, `texturePackerCompress`) → `packages/symbols-cyanotype/assets/`. Атлас «Водолаза» з формату Pixi переписується у формат Spine (`diver.atlas`), поруч — скелет `diver-skeleton.json` з `src/diver.ts`. Гра завантажує атлас символів (`loadCyanotypeAtlasPack`) замість растеризації SVG на старті; галерея паку лишає растеризацію в браузері, щоб показувати пак без кроку збірки.

«Водолаз» у `Fx.bigWin`: `Spine` з `autoUpdate: false`, час — від тікера GSAP помножений на `globalTimeline.timeScale()`, тож пропуск, сповільнення (запис відео) і прискорення (тести) діють і на нього.

## Джерело результатів (GDD §5)

`LocalResultSource.request()`:
1. Якщо `stepId` збігається з останнім — повертає збережений результат (повтор після втраченої відповіді або подвійного кліку).
2. Інакше виконує `step()` і записує `{ engine, lastResult, current, history }` одним `store.set` — результат, баланс і банки атомарні. Старі сесії без банок завантажуються з порожніми (`engine.pots ??= {}`).
3. Опційна імітація мережі: затримка й «втрата» запиту до або після фіксації (налаштування «Імітувати нестабільну мережу»).

Клієнт повторює той самий `stepId`, доки не отримає відповідь.

## Клієнт (GDD §3, §4)

`GameFlow` — єдина точка переходів (`go()`), таблиця `TRANSITIONS` відповідає таблиці переходів GDD:

| GDD | Код |
|---|---|
| Завантаження → відновлення або база | `boot()`, `resume()` |
| База → Обертання (одне списання) | `startRound()` → `reelStep('spin')` |
| Обертання → Очікування | `ReelSet.stop()` з `anticipate(i)`: ≥5 перлин або дві карти на 2–3 барабанах |
| Розбір результату | `presentReelResult()` |
| Вхід у Salvage, Респін, Super | `runSalvage()`, `salvageLoop()`, `SalvageBoard.superWave()` |
| Розкриття → Збір | `SalvageBoard.reveal()`, `collect()`, потім крок `collect` |
| Free Dives, підсумок | `freeDivesIntro()`, `freeDivesLoop()`, `Fx.summary()` |
| Перезавантаження в активному режимі | `resume()` — продовжує з останнього підтвердженого кроку |

Керування й подача за схемою 3 Oaks:

- Стовпчик праворуч: спін, автогра, кнопка ставки з сіткою з 16 рівнів. Швидкість і звук у кутку, внизу лише баланс і виграш.
- «Спін» реагує на натискання (`pointerdown`/пробіл), а не на `click`. Коротке натискання — спін, quick stop або пропуск. Утримання ≥0,4 с вмикає `settings.holdTurbo`, і `GameFlow.startRound` запускає наступний раунд одразу після завершення попереднього, доки кнопку не відпустять (`spinDown` / `spinUp`).
- Автогра: `AutoConfig` у `client/core/settings.ts` (кількість раундів, «зупинити на бонусі», «на будь-якому виграші», «разовий виграш більший за», «баланс зріс на», «баланс зменшився на»; суми в центах). `GameFlow` пам’ятає баланс на старті автогри й після кожного завершеного раунду перевіряє умови в `autoShouldStop()`. Бонус зупиняє автогру одразу на тригері, якщо так налаштовано. Налаштування зберігаються в `prefs`.
- Рядок фіксованих нагород над полем (`view/JackpotBar.ts`) показує суми для поточної ставки; `SalvageBoard.onJackpot` «засвічує» бирку, коли нагорода падає або відкривається з мушлі. `GameView.layout` перемикає широке і портретне компонування: на портреті бирки йдуть у два ряди (3 + 2), а поле зсувається нижче.
- Стартовий екран (`hud/StartScreen.ts`) займає місце завантажувача: спершу прогрес кроків завантаження, потім чотири картки фіч зі справжніми картинками символів і кнопка «Грати». «Більше не показувати» пише `prefs.startScreen = false` (вмикається назад у налаштуваннях).
- Екрани бонусів (`hud/BonusScreen.ts`): перед Salvage і Free Dives — екран, що чекає гравця й перелічує активні банки («Extra: 4 респіни замість 3»), після — підсумок. В автогрі й turbo вони закриваються самі (`GameFlow.screenAutoMs`).
- Банки (`view/Jars.ts`): ліворуч від поля на широкому екрані й рядком над полем на портреті. `GameView.flyMark` летить міткою від перлини до горловини банки зі слідом і бризками; повна банка позначається READY, на старті Salvage «виливається» в поле (`pourStream`), а активні показують ON.
- Перехід у бонус (`view/Plunge.ts`): спалах експозиції, кільця, бульбашки й поштовх «камери» поверх зміни середовища.

Таймінги з §4 зібрані в `SPEED_PROFILES` пакета `@slotkit/core` (гра реекспортує їх як `PROFILES`); quick і turbo — пропорційно коротші. Увесь ігровий час іде через GSAP, тому прихована вкладка, де браузер зупиняє `requestAnimationFrame`, заморожує і анімації, і очікування; звук призупиняється окремо.

Захист від зависань (після звіту з iOS, де бонус застряг у стані `reveal`):

- Глобальну шкалу GSAP вручну більше не ставимо на паузу. `wake()` перезапускає тікер на `visibilitychange`, `pageshow`, `focus` і першому дотику.
- `play()` резолвиться і тоді, коли таймлайн убили (`onInterrupt`), тож потік не чекає мертвий твін.
- Сторож у `GameFlow.startWatchdog()`: якщо поза очікуванням гравця 20 с немає жодного переходу, поточний епізод пропускається; після 32 с з’являється пропозиція відновити гру з останнього підтвердженого кроку.
- Кожен перехід і помилка йдуть у кільцевий журнал `diagnostics`; «Налаштування → Копіювати діагностику» кладе звіт (стан, трасу, версію збірки, user agent) у буфер обміну.

Пропуски: `Episode` доводить усі зареєстровані таймлайни до кінця, і кожен сигнал завершення спрацьовує рівно один раз; наступні кроки епізоду виконуються миттєво.

Барабани: посадка — твін пройденої відстані з фіксованою тривалістю, тож момент удару детермінований, і барабани стають строго по черзі навіть при quick stop.

Усі анімації символу рухають лише внутрішній шар `body` і стартують зі спільного скидання, тож посадка, виграш і блиск не конфліктують між собою.

## Графіка й звук (GDD §6)

- Стиль — ціанотипія (Anna Atkins, 1843): синій папір, білі фотограми предметів, паспарту з підписом «Plate I — Surface», кораловий олівець лише для грошей і виграшів.
- Символи — SVG-фотограми в пакеті `@slotkit/symbols-cyanotype` (`src/svg.ts`): руни як трафаретні жетони з вирізаним гліфом, компас, шолом, переріз наутилуса, ліхтар, карта, перлини, мушля закрита/відкрита, медальйони фіксованих нагород із бирками. Пак растеризує їх (`createCyanotypePack`) разом із «розмитими» версіями для обертання; зерно паперу — `feTurbulence` усередині SVG. `client/art/textures.ts` додає лише графіку гри: середовища, штампи, банки.
- Три середовища — `view/Environment.ts`: поверхня, маршрут Free Dives, морське дно (папір різної експозиції з плямами проявки й водоростями-фотограмами); занурення — рух «камери» між ними.
- Олівцеві лінії й обведення — `pencilLine` / `pencilLoop` з `@slotkit/board`, штампи — `Fx.stampTexture` (canvas із потертостями).
- Звук — `audio/AudioEngine.ts`: три музичні петлі (база, Free Dives, Salvage) і синтезовані ефекти (зупинка, посадка, reset, Super, reveal, підсумок, гул очікування, що обривається при невдалому тригері). Для 3 Pots — політ мітки, «ковток» банки, повна банка, виливання, Boost і Multi.
